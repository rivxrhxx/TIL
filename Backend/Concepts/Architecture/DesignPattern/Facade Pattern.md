# Facade 패턴이란?

복잡한 **서브시스템을 사용하기 편하게** 간단한 인터페이스로 제공하여 클라이언트와의 결합도를 낮추는 구조적 디자인 패턴

여러 클래스나 인터페이스가 복잡하게 얽혀 있는 시스템에서 단순한 인터페이스를 제공함으로써

사용자는 서브시스템의 복잡한 내부 구현을 몰라도 쉽게 기능을 사용할 수 있다.

클라이언트는 복잡한 내부 구조를 몰라도 Service의 호출만으로 쉽게 기능을 사용함

## Facade 왜 사용하는가?

1. 시스템이 너무 복잡할때 간단한 인터페이스를 통해 복잡한 시스템에 접근하고싶을떄
2. 시스템을 사용하고 있는 외부와 결합도가 너무 높을 때 의존성 낮추기 위할때

## Facade의 장점

1. 하위시스템의 복잡성에서 코드를 분리해 외부에서 시스템 사용하기 EASY
2. 하위시스템 간의 의존 관계가 많을 경우 이를 감소시키고 의존성을 한곳에 모을수있다
3. 복잡한 코드를 감춤으로써 클라이언트가 시스템 코드를 모르더라도 Facade클래스만 이해하고 사용가능

## Facade의 단점

1. 파서드가 앱의 모든 클래스에 결합된 God 객체가 될수도있음
2. 파서드 클래스 자체가 서브시스템에 대한 의존성을 가지게되어 의존성을 완전히 피할수없음
3. 따라서 추상화 하고자하는 시스템이 얼마나 복잡한지 퍼사드 패턴을 통해서 얻게 되는 이점과 추가적인 유지보수 비용을 비교해보며 결정하여야 한다
